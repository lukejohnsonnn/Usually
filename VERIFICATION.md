## 2026-11-16 styling + entry grid fix (live-site look report)
Luke confirmed on the live site (https://usually-wnsi.onrender.com) that it looked "completely different... glitchy" vs the Muse version. A browser check + repo styles read found two real differences, both in this repo client, not rendering failures: (1) `--bg:#ffffff` / `--card:#f8f9fb` — the warm paper background never carried over from the Muse version; (2) `main{justify-content:center}` vertically centered content, leaving big empty white bands on tall screens. He also confirmed the 100-dot grid never showed while answering, and the dot colors were wrong.
- **Warm paper + top-anchored layout.** `client/styles.css` now uses `--bg:#faf5ec` (warm paper), `--card:#fffdf7`, `--line:#e7dcc4` (warm borders/track), and `main{justify-content:flex-start}` so content starts at the top on home and playing screens. All white surfaces (ghost buttons, inputs, overlay cards, vote-no) now use the warm card color; slider track/fill use the warm line color.
- **Entry grid on the answering screen.** `showRound` in `client/app.js` now renders a compact `<div id="entry-grid" class="grid entry">` (220px wide, ~220px tall — question + grid + slider + Lock still fit one 390×844 phone screen with no scrolling) on every Guess and Split round, between the big-guess readout and the slider/controls. It lights live as the slider moves via `renderEntryGrid()`, called from `sync()` and from the fine-tune OK callback.
- **Dot colors, Muse-exact.** New `--dot-unlit:#c9bda0` — a warm grey clearly visible on the paper (the old `#e3e5e8` was nearly invisible). Reveal unchanged in meaning: crowd = solid navy, your guess = gold ring, overlap = navy + gold ring, unlit = warm grey; Split = navy vs poppy halves with the split gold-ringed. `renderGrid` gained entry modes that carry no crowd data: `{entry:"guess", value}` (gold rings on the dots up to the current guess; hundredths use 0.01 steps) and `{entry:"split", left}` (navy/poppy halves, split gold-ringed). The fine-tune hundredths grid now uses the same gold language instead of navy fill.
- **How to Play: no scoring math.** A grep of the whole repo (client, server, lib, scripts, data) and of the live served page found NO point ranges anywhere — the overlay already said only "The closer your guess, the more points. A perfect guess is a Bullseye." The earlier "0–20 points off = 100 pts" sighting was not in the served files. Regression checks now pin the absence.
- **Bug caught by the new tests:** the first cut of the entry branch read `spec.entry.value` / `spec.entry.left`, but the specs are `{entry:"guess", value}` / `{entry:"split", left}` — the value lives on `spec`, not on `spec.entry` — so no dots ever lit. The renderGrid stub tests caught it (entry guess 50 / hundredths 37 / entry split all failed); fixed to `spec.value` / `spec.left` and the suite went green.
